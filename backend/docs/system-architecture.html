콜록(Collog) 시스템 구성도

기준일 2026-08-17 · 저장소 Frekion2002/14th-hackathon · 근거는 backend/docker-compose.yml, backend/deploy/, backend/app/services/, HANDOFF.md

구현됨 저장소 코드/Compose에 존재하고 실행 검증된 것 미구현 권장하지만 아직 저장소에 없는 것 외부 외부 SaaS. 우리가 운영하지 않는다
이 문서가 구분하는 두 가지. 현재 구현 상태는 docker compose up으로 지금 뜨는 구성이다. TLS 종단이 없고 iOS가 http://, ws://로 직접 붙으며 MinIO 9000이 그대로 열려 있다. 권장 운영 구성은 그 앞에 Caddy를 두는 형태이며 저장소에 아직 없다. 데모는 현재 구성 + iOS ATS 예외로 진행한다.

1. 구성 요소

클라이언트 — iOS 네이티브 (Swift, 배포 타깃 iOS 17.0)
자녀 앱 구현됨
발신. CallKit CXStartCallAction → LiveKit publish. 연결 대기 중 오늘의 질문 재생
부모 앱 구현됨
수신. PushKit → CallKit → /accept → LiveKit. 분석용 PCM을 로컬에서 기록해 업로드
동일 바이너리
역할은 로그인 계정의 role로 갈린다. 앱은 하나다
발신·수신 모두 CallKit을 거친다. didActivate 이후에만 마이크를 publish하므로 오디오 세션 획득 경로가 양쪽에서 같다.
↓
경계 — TLS 종단 / 리버스 프록시
Caddy 미구현
/api → FastAPI, rtc 서브도메인 → LiveKit signaling. Let's Encrypt 자동 발급. Compose에 서비스가 아직 없다
도메인 / 인증서 미결정
공인 IP만으로는 Let's Encrypt를 받을 수 없다. 무료 도메인+LE / ATS 예외 확대 / 자체 서명 중 선택이 남았다
↓
애플리케이션 — 단일 인스턴스 Docker Compose
FastAPI backend 구현됨
Python 3.12, async SQLAlchemy. 27 paths / 28 operations. 통화 orchestration, 분석 파이프라인, 리포트
LiveKit Server v1.13.1 구현됨
self-hosted SFU. room/token 발급은 backend가 서버 API로 한다. LiveKit Cloud는 쓰지 않는다
LiveKit Egress v1.12.0 구현됨
Track Egress로 화자별 Opus OGG 분리 저장. Room Composite/Chrome 경로가 아니라 트랙 복사에 가깝다
↓
상태 저장 — 인스턴스 내부
PostgreSQL 17 구현됨
사용자·가족·동의(append-only)·통화·추출·기준선·signal·리포트. 기동 시 schema guard가 모델과 대조
Redis 7.4 구현됨
LiveKit ↔ Egress 사이의 job 버스. 애플리케이션 캐시로는 쓰지 않는다
MinIO 구현됨
S3 호환. 원본 OGG/PCM 임시 보관과 질문 TTS MP3 캐시. 버킷 collog-audio
↓
외부 API — backend에서만 호출한다. 키는 iOS로 내려가지 않는다
Deepgram Nova-3 외부
api.deepgram.com. language=ko. 화자별 트랙을 각각 전사해 utterance/word timing 보존
Gemini 외부
generativelanguage.googleapis.com. 기본 gemini-3.6-flash. structured output으로 증상·복약·활동·수면만 추출
ElevenLabs 외부
api.elevenlabs.io. eleven_flash_v2_5, language_code=ko. 연결 대기 질문 MP3. 실패 시 iOS 로컬 TTS 폴백
APNs 외부
api.sandbox.push.apple.com. .p8 ES256 JWT로 VoIP push. 현재 키는 sandbox 전용

현재 저장소 구성은 위 그림에서 Caddy 상자만 빠진 형태다. iOS가 http://<host>:8080, ws://<host>:7880, http://<host>:9000에 직접 붙는다. Caddy를 넣으면 8080/7880은 닫고 443만 열 수 있지만, UDP 7882는 프록시 대상이 아니라 항상 직접 열려 있어야 한다.

     |------------------->|                   |                    |
     |                    | 동의/프로필 검증  |                    |
     |                    | room + 자녀 token |                    |
     |                    |------------------>|                    |

     |                    |                   |                    |
     |                    |  APNs VoIP push   |                    |

     |                    |   payload = callId/callUUID/callerId/    |

불변조건이유
APNs payload에 LiveKit 토큰과 건강정보를 넣지 않는다 push는 인증 경로가 아니다. 부모 토큰은 인증된 /accept 응답에서만 발급한다
최신 부모 동의가 GRANTED가 아니면 Egress와 PCM 업로드를 시작하지 않는다 동의 없는 통화는 허용하되 분석은 하지 않는다. 없으면 CONSENT_REQUIRED
화자 분리는 Track Egress로만 한다 Participant Egress는 transcode 경로여서 이 스택의 OGG와 호환되지 않았다. 트랙이 이미 분리되므로 Deepgram diarization 애드온도 필요 없다
마이크 publish는 CallKit didActivate 이후에만 한다 LiveKit isAutomaticConfigurationEnabled를 끄고 엔진을 .none으로 시작하므로, 그 전에는 오디오 장치를 잡지 않는다

6. 클라우드 배포에서 반드시 바꾸는 것

항목로컬 LAN공인 IP 뒤틀리면
LiveKit 설정 파일 deploy/livekit.yaml
use_external_ip: false		 LIVEKIT_CONFIG_FILE=livekit-cloud.yaml
use_external_ip: true		 LiveKit이 사설 IP를 ICE 후보로 광고한다. 연결되고 무음이 된다. 자동 탐지가 실패하면 rtc.node_ip를 직접 적는다
iOS가 붙는 주소 3개 Mac의 LAN IP PUBLIC_BASE_URL, LIVEKIT_URL, S3_PUBLIC_ENDPOINT_URL 모두 공인 IP 하나만 사설이면 그 기능만 조용히 실패한다
스키마 처리 SCHEMA_AUTO_RESET=true SCHEMA_AUTO_RESET=false Alembic 도입 전이라 빈 DB는 FRESH 판정으로 기동을 거부한다. 첫 기동만 true로 올린 뒤 되돌린다
팀 포털 TEAM_PORTAL_ENABLED=true 인터넷 직결이면 false 키 값은 노출하지 않지만 provider 구성 상태가 공개된다
Track Egress 양쪽 모두 켠 정상 구성. ALLOW_RAW_ONLY_ANALYSIS는 기본 false로 두고, 4 GB 실측이 실패할 때만 켠다 raw-only로 켜면 부모 PCM만으로 분석하고 Egress 호출을 0회로 만든다
4 GB에 들어가는가는 아직 추정이다. Egress는 Room Composite(Chrome) 경로가 아니라 Track Egress이고, shm_size: 1gb는 메모리 선점이 아니라 /dev/shm tmpfs 상한이다. 그래서 스택 합계를 약 1.3 GB로 추정하고 정상 구성으로 배포하기로 했지만, 실측치는 아직 없다. 2026-08-18 배포 시 free -m과 docker stats를 남기고 이 문단을 실측으로 교체한다.

7. 아직 없는 것

항목상태영향
Caddy / TLS 종단미구현 Compose에 서비스가 없다. iOS는 Info.plist ATS 예외로 HTTP를 쓴다
도메인과 인증서 방식미결정 공인 IP만으로는 Let's Encrypt를 받을 수 없다
livekit-cloud.yaml 실서버 검증미검증 파일은 있지만 공인 IP 환경에서 미디어가 실제로 붙는지 확인하지 않았다
내구성 있는 작업 큐미구현 분석 재시도와 정리가 FastAPI 프로세스의 background task다. 재시작하면 유실된다
Alembic 마이그레이션미구현 schema guard만 있다. 배포 환경은 스키마를 수정하지 않고 기동을 거부한다
기침 detector비활성 HeAR ONNX로 교체했지만 cough_detector_validated=false다. 실제 통화 조건 측정 전에는 값을 만들지 않는다
APNs production 키미발급 현재 .p8는 sandbox 전용. TestFlight/App Store 빌드는 거부된다
이 문서는 HANDOFF.md의 하위 문서다. 구성이 바뀌면 코드와 같은 커밋에서 이 파일과 HANDOFF.md를 함께 갱신한다. 비밀값과 실제 건강정보는 기록하지 않는다. 상세 절차는 backend/docs/cloud-deploy.md, backend/docs/two-iphone-e2e.md, backend/docs/schema-management-design.md에 있다.
