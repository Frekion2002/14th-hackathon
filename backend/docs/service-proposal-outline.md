# 콜록(Collog) 서비스 기획안 - 개조식 수정본

작성 기준: 2026-08-13

> 초기 기획안의 문제의식과 사업 구조를 유지하되, 현재 확정된 제품 구조와 실제 구현·검증
> 상태를 반영했다. 의료 진단으로 오해될 표현과 검증되지 않은 음향 성능 주장은 제거했다.

## 0. 한눈에 보는 서비스

- 서비스명: 콜록(Collog)
  - `Call`과 `Log`의 합성어
  - 가족 간 통화를 개인 건강 변화 기록으로 전환하는 iOS 통화 서비스
- 핵심 한 문장
  - 평소 가족 통화에서 나온 건강 관련 자기보고와 음성 변화를 기록해, 지난 통화와 달라진 점을
    가족에게 보여주는 서비스
- 핵심 가치
  - 새로운 돌봄 행동을 요구하지 않음
  - 이미 반복되는 가족 통화를 활용
  - 기억에 의존하던 안부 정보를 시간 순서가 있는 기록으로 전환
- 서비스 경계
  - 질환 진단·위험군 판정·응급도 판단·치료 지시를 제공하지 않음
  - 사용자가 직접 말한 내용과 검증된 관찰값만 표시

## 1. 서비스 소개 및 문제 정의

### 1-1. 해결하려는 문제

- 비동거 가족의 건강 변화 인지 지연
  - 자녀가 부모와 정기적으로 통화해도 점진적 건강 변화를 알아채기 어려움
  - 변화가 누적된 뒤 진단·입원·낙상·수술 등의 사건으로 처음 인지하는 경우 발생
- 건강 안부 통화의 정보 손실
  - 통화 당시 들은 내용을 별도로 기록하지 않음
  - 다음 통화에서는 지난 답변과 비교하기 어려움
  - 병원에서 “언제부터 그랬는지” 질문을 받아도 정확히 답하기 어려움

### 1-2. 문제의 원인

- 축소 보고
  - 가족에게 걱정을 끼치지 않기 위해 “괜찮다”고 짧게 답하는 경향
- 제한된 관찰 범위
  - 음성 통화에서는 걸음걸이·식사 상태·약통·생활 환경을 직접 볼 수 없음
- 점진적 변화에 대한 적응
  - 자주 통화할수록 작은 변화가 익숙해져 이전 상태와의 차이를 놓칠 수 있음
- 질문 지식 부족
  - 가족이 질환별로 무엇을 확인해야 하는지 알기 어려움
- 기록 부재
  - 건강 관련 답변이 통화 종료와 함께 사라짐

### 1-3. 초기 기획안의 시장 근거

- 비동거 가족
  - 만 19~34세 15,098가구 중 부모와 떨어져 사는 비율 45.6%
  - 출처 표기: 국무조정실·한국보건사회연구원 청년 실태조사
- 늦은 발견에 따른 부담
  - 폐암 5년 생존율: 국한 병기 81.5%, 원격전이 13.9%
  - 전이 후 진단 비율 40.7%
  - 출처 표기: 국가암등록통계
- 고령층 의료비 부담
  - 65세 이상 1인당 연평균 진료비 550만 8천 원
  - 전체 평균의 2.4배
  - 출처 표기: 2024 건강보험 통계연보
- 발표 전 확인 사항
  - 통계의 정확한 조사명·발행연도·페이지·모수 정의 재확인
  - 생존율·진료비를 콜록의 직접 효과로 연결하는 인과 표현은 사용하지 않음

### 1-4. 핵심 타깃

- 핵심 사용자
  - 부모와 떨어져 사는 20~30대 자녀
  - 디지털 서비스 사용이 가능한 50~60대 부모
- 1차 집중 사용자
  - 최근 2년 안에 부모의 진단·입원·낙상·수술을 경험한 자녀
  - 부모의 병원비 또는 돌봄 비용을 직접 부담한 경험이 있는 자녀
  - 부모의 만성질환·복용약·생활 변화를 지속적으로 확인하고 싶은 가족
- 제품 확장
  - 데이터 모델은 부모·자녀 어느 가족 구성원도 건강 기록의 주체가 될 수 있게 설계
  - 핵심 시연 메시지는 비동거 자녀의 부모 건강 관리에 집중

### 1-5. 기존 서비스와의 차이

- 기존 AI 안부전화
  - 지자체·기관이 독거노인 또는 취약계층에게 전화를 발신
  - AI 전화 수신 여부가 서비스 성립의 전제
  - 결과가 행정·돌봄 담당자 중심으로 전달
- 콜록
  - 가족이 원래 하던 통화에 질문 안내와 분석을 결합
  - 부모에게 별도의 AI 전화 응답 행동을 요구하지 않음
  - 실제 건강 관련 행동을 결정하는 가족과 본인이 결과를 열람
  - 일회성 안부 확인이 아닌 개인별 종단 기록을 축적

## 2. 핵심 사용자 흐름

### 2-1. 온보딩·동의

- 앱 최초 실행 시 필수 동의 완료
  - 민감 건강정보 수집·이용
  - 통화 음성 분석
  - 음향 특징 추출
  - 가족 리포트 공유
- 필수 동의 미완료 시 홈·통화 기능에 진입하지 않음
- 서버에서도 두 통화 참여자의 최신 동의 상태 확인
- 동의 철회 시
  - 이후 통화 분석 중단
  - 기존 가족 공유 권한 차단
  - 파생 건강 관찰·리포트 삭제 작업 수행

### 2-2. 가족 초대·프로필 확인

- 가족 초대 방법
  - 카카오톡 링크
  - 문자 링크
  - 초대 코드
- 초대받은 사용자 흐름
  - 초대 확인
  - 로그인
  - 필수 동의
  - 가족이 제안한 건강 프로필 확인·수정
- 프로필 권한
  - 가족이 먼저 입력한 정보는 `가족 제안` 상태
  - 건강정보 당사자가 확인해야 확정 프로필로 사용

### 2-3. 건강 프로필

- 진단받은 질환
  - 당뇨·고혈압·고지혈증·천식·비만
  - 호흡기·관절·심장질환
  - 기타 질환
- 복용약
  - 약 이름
  - 복용 시간·횟수
  - 복용 목적
  - 현재 복용 여부
  - 용량은 선택 입력
- 건강 걱정
  - 진단받지 않았지만 본인이 관리하고 싶은 항목
  - 예: 기억력·수면·호흡·통증·식욕 변화
- 데이터 원칙
  - 질환과 걱정을 구분
  - 입력자·확인자·수정 이력 보존

### 2-4. 오늘의 건강 질문

- 질문 생성 기준
  - 통화 상대방의 확정 건강 프로필
  - 복용약
  - 이전 통화의 지속 확인 항목
  - 최근 질문 중복 여부
- 질문 구성
  - 비교용 기준 질문 1개
  - 프로필·이전 기록 기반 동적 질문 1개
- 질문 예시
  - 수면: “어젯밤 잠은 어땠어요?”
  - 복약: “오늘 약은 언제 챙겨 드셨어요?”
  - 활동: “오늘 밖에서는 어떻게 움직이셨어요?”
  - 호흡: “밤에 기침이나 숨이 불편해서 깬 적이 있었어요?”
- 안전 원칙
  - 검수된 질문 템플릿에서 선택
  - LLM이 임의로 의료 문진을 자유 생성하지 않음
  - 예·아니오보다 구체적인 답을 유도하는 질문 우선

### 2-5. 통화 연결 질문 TTS

- 전화 발신 후 상대방이 수락하기 전까지 질문 재생
- ElevenLabs가 우선순위 1위 질문을 발신자에게 안내
- 상대방에게 TTS를 송출하지 않음
- 상대방이 수락하면 TTS 즉시 중단
- ElevenLabs 장애 시 iOS 한국어 내장 TTS로 대체

## 3. 통화 분석 및 건강 기록

### 3-1. 양 참여자 분석

- 발신자와 수신자의 음성 track을 분리
- 두 사람 모두 각자의 건강 분석 대상
- 각 결과를 본인의 타임라인·리포트에 저장
- 한 사람의 발화량 부족 또는 분석 실패가 다른 사람의 성공 결과를 막지 않음
- 연결 질문은 통화 상대방을 대상으로 하지만 자유 대화에서 나온 양쪽 건강 발화도 각각 기록

### 3-2. 전사·대화 내용 구조화

- STT
  - Deepgram Nova-3 한국어 모델 사용
  - 양쪽 음성을 각각 전사한 뒤 시간 순서로 결합
- LLM
  - Gemini structured output 사용
  - 두 사람의 결과를 `subjectUserId`로 분리
- 추출 범주
  - 증상
  - 복약
  - 활동
  - 수면
  - 식사
  - 일상 기능
- 근거 규칙
  - 당사자가 직접 말한 내용만 건강 사실로 저장
  - 직전 질문과 실제로 이어진 짧은 답변만 질문·답변 쌍으로 해석
  - 다른 가족의 추측·질환 진단·원인·치료 지시는 저장하지 않음

### 3-3. 음향 관찰

- 후보 지표
  - 발화 속도
  - 휴지 비율
  - 기본주파수 변동
  - 기침 의심 이벤트
  - 되묻기·대화 수리 표현
  - 질문 후 응답 시작 지연
- 표시 원칙
  - 질환 진단 근거가 아닌 보조 관찰값
  - 본인의 동일 시간대 과거 기록과만 비교
  - 검증되지 않은 지표는 `측정 불가`로 처리하고 사용자 화면에서 숨김
- 기침 표시 예시
  - “분석 가능한 12분 동안 기침 의심 구간 3건이 관찰됐어요.”
  - “기침이므로 특정 질환이 의심된다”는 식으로 표시하지 않음
- 되묻기 표시 예시
  - “다시 말해 달라는 표현이 이전 통화보다 늘었어요.”
  - 난청·인지저하 판정으로 변환하지 않음

### 3-4. 개인 기준선

- 인구집단 평균이 아닌 본인의 과거 통화와 비교
- 같은 시간대 통화끼리 비교
  - 오전
  - 오후·저녁
- 최소 기준선
  - 4개 달력 주
  - 주당 유효 통화 1회 이상
- 기준선 준비 전
  - 변화 해석을 제공하지 않음
  - `기준선 수집 중`으로 표시
- 출력 예시
  - “최근 3주 동안 같은 시간대 통화보다 말하는 속도가 느렸어요.”
  - “지난달보다 수면 불편을 언급한 통화가 늘었어요.”

### 3-5. 저장·폐기 원칙

- 원본 오디오
  - 분석 완료 또는 실패 후 폐기
- 전체 STT 전사
  - 처리 중에만 사용
  - 처리 완료 후 폐기
- 장기 저장
  - 건강 관련 최소 근거 문장
  - 중립적으로 구조화한 건강 관찰
  - 음향 특징값과 측정 상태
  - 통화·분석 시각과 모델 버전
- 사용자 권리
  - 본인 리포트 열람
  - 가족별 공유 범위 설정
  - 동의 철회·계정 삭제

## 4. 리포트와 행동 전환

### 4-1. 통화 직후 결과

- 이번 통화에서 당사자가 직접 언급한 건강 내용
- 분석된 통화 시간과 데이터 충분성
- 검증된 음향 관찰
- 다음 통화에서 확인할 항목
- 분석 실패·발화량 부족 시 명시적 상태 표시

### 4-2. 주간·월간 리포트

- 기간
  - 달력 기준 주간
  - 달력 기준 월간
- 변화 상태
  - 새로 나타남
  - 지속됨
  - 줄어듦·해소됨
  - 불확실
  - 데이터 부족
- 리포트 구성
  - 건강 대화 항목 변화
  - 검증된 음향 추세
  - 비교 기간·근거 통화 수
  - 다음 통화 질문
- 생성 방식
  - 변화 상태와 수치는 규칙 기반으로 결정
  - Gemini는 제공된 근거 범위에서 문장을 정리

### 4-3. 건강 타임라인

- 통화별 건강 자기보고 기록
- 검증된 음향 변화
- 건강 프로필 변경 이력
- 날짜와 근거 출처를 구분해 표시
- 진료 시 참고할 수 있는 1페이지 요약으로 확장 가능
- 의료진 제출용 진단 자료가 아닌 사용자 기억 보조 자료로 명시

### 4-4. 가족 공유

- 건강정보 당사자가 가족 구성원별 공유 범위 설정
- 공유 항목
  - 건강 프로필
  - 주간·월간 리포트
  - 건강 타임라인
- 기본 공유는 구조화 요약
- 원문 근거는 당사자가 별도로 허용할 때만 표시

## 5. 기술 구성과 실현 가능성

### 5-1. 시스템 구성

- iOS 클라이언트
  - Swift
  - PushKit·CallKit
  - LiveKit iOS SDK
- 통화 서버
  - self-hosted LiveKit
  - 분리된 양쪽 audio track
- 백엔드
  - FastAPI
  - PostgreSQL
  - Redis
  - MinIO
- AI·음성
  - STT: Deepgram Nova-3 한국어
  - LLM: Gemini structured output
  - TTS: ElevenLabs, iOS local fallback
  - 음향: 별도 versioned 분석 pipeline

### 5-2. 처리 흐름

1. 발신자가 가족 구성원 선택

## 8. 초기 기획안에서 정정한 표현

- `Gemini STT`
  - 정정: Deepgram Nova-3가 STT, Gemini는 구조화 추출·문장 정리 담당
- `자녀가 부모를 분석`
  - 정정: 통화의 발신자와 수신자 모두 각자의 건강 기록 대상으로 분석
- `동의하지 않으면 분석 비활성 통화`
  - 정정: 필수 동의를 최초 온보딩 완료 조건으로 두어 정상 통화는 항상 양쪽 분석
- `되묻기 빈도는 청력 및 인지 신호`
  - 정정: 통화 환경·습관 영향을 받는 대화 수리 관찰값이며 난청·인지저하 판정이 아님
- `괜찮다는 말을 음향이 반증`
  - 정정: 대화 내용과 음향 관찰을 나란히 제공할 수 있으나 모순이나 질환을 자동 판정하지 않음
- `스마트폰 기침 탐지 민감도 91%, 특이도 98%`
  - 정정: 특정 연구·데이터셋 결과를 현재 콜록 통화 환경 성능으로 사용할 수 없음
- `음향 지표 4종은 검증이 명확함`
  - 정정: 현재 발화 속도 외 지표는 보정·실기기 검증이 필요하며 미검증 값은 숨김
- `4주 비교로 정확도 확보`
  - 정정: 4주는 기준선 수집 정책이며 정확도 보장을 뜻하지 않음
- `AI가 질문을 생성`
  - 정정: 검수된 질문 템플릿을 규칙으로 선택하고 LLM 자유 의료 문진은 제한
- `진료용 타임라인`
  - 정정: 진료 시 참고 가능한 사용자 기억 보조 자료이며 의료 문서가 아님
